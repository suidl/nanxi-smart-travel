# 楠溪智游参赛项目设计说明

## 1. 项目定位

项目名称：楠溪智游

参赛方向：赛道一「人工智能体（AI Agent）」— 命题二「AI Agent × 永嘉特色产业」— 文旅智能导览方向。

一句话定位：面向楠溪江自由行游客的动态行程决策智能体，根据同行人、预算、天气和途中变化，自主调用工具生成并重排可执行行程。

核心差异：不做通用旅游问答。产品必须呈现“理解约束—拆解任务—调用工具—校验结果—生成行程—响应变化并局部重排”的完整业务闭环。

## 2. 目标用户与核心场景

首版聚焦家庭自由行游客，尤其包含老人或儿童的同行组合。

评委演示采用固定场景：一家三口周六从温州南站出发，包含一位老人和一名儿童，预算 1200 元，希望体验山水与古村文化。系统查询天气、景点、路线和预算后生成一日行程；随后触发“午后阵雨”情境，系统保留已完成行程，将后续户外段替换为室内或低风险文化体验，并重新计算路线、时间和预算。

## 3. 首版功能范围

### 3.1 创建行程

- 采集出发地、日期、同行人、预算、偏好、步行承受度和饮食需求。
- 支持自然语言输入与结构化表单互相同步。
- 对缺失的关键条件进行追问，不直接生成低可信方案。

### 3.2 自主规划

- 将用户目标拆分为天气查询、景点筛选、开放时间校验、路线排序、预算核算和风险检查。
- 在页面中展示经过压缩的任务计划、工具名称、输入摘要、执行状态和结果证据，不展示模型隐含推理过程。
- 最终方案必须通过时间冲突、预算上限、开放时间、步行强度和天气适配校验。

### 3.3 行程驾驶舱

- 采用已确认的 A 布局。
- 左侧为创建行程、行程驾驶舱、我的行程、文化图鉴导航。
- 中间为路线示意、时间轴、景点安排、交通时间和预算。
- 右侧为 Agent 执行轨迹、工具调用状态、证据来源和风险提示。
- 提供“开始导航”“导出 PDF”“添加到日历”“分享行程”操作。

### 3.4 动态重排

- 支持下雨、景点关闭、道路拥堵、老人疲劳和预算调整五类变化。
- 已完成节点保持不变，仅重排当前时间之后的安排。
- 展示调整前后差异、替换原因、时间变化和预算变化。
- 演示按钮产生的情境必须明确标注“演示情境”，不伪装为实时事件。

### 3.5 最终交付结果

- 保存可再次打开的行程记录。
- 生成适合打印和手机查看的 PDF 行程单。
- 生成标准 ICS 日历文件。
- 生成景点导航入口和可分享的只读行程页面。

## 4. 智能体与工具架构

系统采用一个行程编排智能体，而不是多个相互聊天的智能体。

编排流程：

1. 约束解析器将自然语言整理为结构化旅行约束。
2. 任务规划器生成可执行任务清单。
3. 工具路由器调用景点库、天气、路线、预算和规则校验工具。
4. 行程优化器根据时间窗、距离、偏好和风险组合候选方案。
5. 结果校验器拒绝超预算、闭馆冲突或不适合目标人群的方案。
6. 输出生成器创建驾驶舱数据、行程说明、PDF 和日历文件。

首版工具：

- `poi_search`：查询楠溪江景点、文化点位、餐饮和交通节点。
- `weather_forecast`：按日期与坐标查询天气预报。
- `route_estimate`：计算点位距离、预计路程和访问顺序；结果明确标注为估算。
- `opening_hours_check`：校验营业时间和计划到达时间。
- `accessibility_check`：校验适老、亲子和步行强度约束。
- `budget_calculator`：计算交通、门票、餐饮和预留费用。
- `itinerary_validator`：执行跨工具结果的最终一致性检查。
- `document_export`：生成 PDF、ICS 和分享数据。

模型接入采用 OpenAI 兼容接口适配层。无密钥时只允许进入明确标记的本地演示模式，用于页面和自动测试；正式提交环境必须配置真实模型服务。

## 5. 数据设计

- 建立带来源信息的楠溪江公开数据集，首版覆盖不少于 25 个景点、文化点位、餐饮或交通节点。
- 每条记录包含名称、分类、坐标、推荐时长、开放信息、费用区间、适老人群、适合天气、步行强度、文化简介、来源链接和信息更新时间。
- 实时天气优先使用无需登录的公开天气接口。
- 路线时间采用可解释的距离估算，并提供高德或其他地图导航入口；不得把估算值表述为实时路况。
- 所有内容型结论保留来源，价格和开放信息显示更新时间。

## 6. 页面结构

1. 欢迎页：一句话价值、示例需求和“开始规划”。
2. 创建行程页：自然语言输入、同行约束和预算表单。
3. 规划过程页：实时展示任务拆解与工具执行进度。
4. 行程驾驶舱：A 布局，作为核心演示页面。
5. 动态重排对比：展示变更原因及新旧方案差异。
6. 我的行程：保存、再次打开、导出和分享。
7. 数据与能力说明：公开数据来源、工具能力、部署结构和免责声明。

## 7. 异常处理与可信性

- 天气接口失败时使用带抓取时间的缓存数据，并醒目标记“非实时”。
- 模型返回无法解析的数据时进行一次结构修复；仍失败则回退到规则规划并提示用户。
- 工具超时、无结果和部分数据缺失分别显示明确状态，不生成虚假结果。
- 开放时间或价格不确定时显示“出发前请复核”，并提供来源入口。
- 不提供在线付款和虚假预订能力，不声称与景区或商户建立合作。
- 分享页面不包含姓名、电话等敏感信息。

## 8. 技术与部署

- 前端：React、TypeScript、Vite，适配桌面演示与手机浏览。
- 后端：Netlify Functions（TypeScript），承载模型调用、天气代理和行程生成。
- 数据：版本化 JSON 公共数据集；行程保存使用 Netlify Blobs。
- 导出：浏览器端生成 PDF 和 ICS。
- 部署：使用 Netlify 生成可公开访问的 HTTPS 链接，并提供环境变量示例和完整部署说明。

## 9. 验证标准

- 单元测试覆盖约束解析、预算计算、开放时间判断、适老规则和动态重排。
- 集成测试验证从需求输入到行程生成的完整工具调用链。
- 异常测试覆盖天气失败、模型格式错误、数据缺失和超预算场景。
- 页面验证覆盖核心桌面视图与常见手机宽度。
- 真实页面演练必须完整复现固定评委场景，并验证 PDF、ICS、分享页和动态重排结果。

## 10. 参赛交付包

- 可运行源代码与必要的示例数据。
- 评委体验链接。
- 项目说明、系统架构、工具清单和集成部署文档。
- 项目名称、Logo、主视觉和界面视觉规范。
- 报名简介、作品摘要、创新点、商业价值和答辩问答材料。
- 16:9 答辩 PPT。
- 五分钟以内 MP4 演示视频、分镜、旁白、字幕和封面。
- 提交文件目录与最终检查清单。

## 11. 明确不做

- 不做酒店、门票或餐饮的真实支付与预订。
- 不做商家后台、会员营销和复杂社区功能。
- 不依赖泵阀、鞋服或民宿企业的私有数据。
- 不把通用聊天能力作为核心卖点。
- 不在首版扩展多日复杂团队游，先保证一日和两日自由行闭环可靠。
